# Recipe Box

Vite single-page app (originally a Lovable prototype). Read README.md for the overview. Public repo: JoshMDiaz/recipe-box.

## Stack

- React 19, TypeScript 6.0, Vite 8, Tailwind 4, Vitest
- Stay on TypeScript 6.x. Don't upgrade to 7: typescript-eslint doesn't support it yet.
- shadcn/ui on Base UI (not Radix). Add components with `pnpm shadcn add <name>`.
- TanStack Router: file-based routes in `src/routes` (the route tree is generated by the Vite plugin). TanStack Query handles data.
- Firebase: Auth (Google sign-in), Firestore and Storage.

## Tooling

- **Package manager: pnpm.** Never use npm, npx or bun. npm would recreate `package-lock.json`, and bun crashes on this Mac because it runs under Rosetta. If a new dependency has install scripts, add it to `allowBuilds` in `pnpm-workspace.yaml`.
- Don't install native tools (Java, etc.) with Homebrew. It's an Intel install running under Rosetta.
- Java 21 (Temurin, in `~/Library/Java/JavaVirtualMachines`) is required by the Firebase emulators.

## Local dev

- `pnpm dev` starts the Firebase emulators and Vite:
  - Auth on :9099
  - Firestore on :8080
  - Storage on :9199
  - Emulator UI on :4000
  - Vite on **:5180**. Port 5173 is taken by other projects.
- Dev runs against the `demo-recipe-box` project, which exists only in the emulators. There is no real Firebase project yet.
- Emulator data is saved to `.emulator-data/` only when the dev server stops cleanly (Ctrl-C). If the process is killed, the session's data is lost.
- Sign-in in dev goes through the Auth emulator's fake Google account picker.
- Before finishing a change, run `pnpm typecheck`, `pnpm lint`, and `pnpm test --run`. If the rules changed, also run `pnpm test:rules`. It starts its own emulators, so stop `pnpm dev` first (same ports).

## Code layout

- Routes that need a signed-in user go under `src/routes/_authed/`. The `_authed.tsx` layout redirects to `/sign-in`.
- `src/features/auth/auth.ts` holds `useUser`, `requireUid`, and sign-in/sign-out.
- `src/main.tsx` clears the Query cache and reruns route guards whenever the signed-in user changes.

`src/features/recipes/`:

- `api.ts`: Firestore and Storage calls
- `queries.ts`: TanStack Query options and hooks
- `parser.ts`: heuristic parser for pasted recipe text (has tests)
- `image.ts`: shrinks photos before upload
- `components/`

## Data and security rules

- Recipes live at `users/{uid}/recipes/{recipeId}`, and photos under `users/{uid}/recipes/{recipeId}/` in Storage. Ownership comes from the path, so there's no owner field.
- The rules live in `firestore.rules` and `storage.rules`, with tests in `tests/rules/`.
- **A new recipe field must also be added to the `hasOnly` key list in the rules**, or writes will be rejected.
